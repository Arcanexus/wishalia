# Languages

Wishalia speaks **French** and **English**. Every screen, the e-mails and the words the API writes
(the name of a first list) follow the reader's language. Dates and amounts are written the way the
reader reads them: « jeudi 24 décembre 2026 » and « 12,50 € » in French, « Thursday, 24 December
2026 » and « €12.50 » in English. Amounts stay in euros: only their format changes.

## Which language a page uses

In this order:

1. **The person's choice.** In the management app, « Réglages » › « Langue » (« Language »):
   `Automatique` (the browser's) or one of the languages. It is kept with the account, so it
   follows them on every device, and copied in the `wishalia.locale` cookie of the device so that the
   sign-in page speaks it too. A guest has no account: the language buttons in the header of the
   public pages and of the sign-in page keep it on their device, in the same cookie.
2. **The browser's language**, from its `Accept-Language` header: the first language Wishalia speaks,
   by weight (`en-US`, `en;q=0.8` and `EN` all read as English).
3. **`DEFAULT_LOCALE`** (`config.defaultLocale` in the chart, `fr` by default), for a browser that
   asks for none of them.

The page says its language to browsers and screen readers (`<html lang>` and a `Content-Language`
header), and a change of language reloads the page so that everything follows.

The magic link e-mail is written in the account's language, or else in the language of the page that
asked for it, or else in `DEFAULT_LOCALE`.

## Where the words are

Every word shown to people lives in `packages/i18n/src/messages/<language>/<area>.ts`, one file per
area:

| Area     | Where it is shown                                                  |
| -------- | ------------------------------------------------------------------ |
| `common` | Shared by every frontend: the skip link, the header buttons.       |
| `app`    | The management app (`apps/web-app`).                               |
| `public` | The public host: its home page, the guests' page, the give form.   |
| `view`   | The cards of the guests' view, in the public page and the preview. |
| `mail`   | The e-mails.                                                       |
| `api`    | The words the API stores, such as the name of a first list.        |

French is the source: each English file is typed after the French one, so the type checker refuses a
missing or an extra key. A sentence that depends on a count or a name is a function
(`wishes: (n) => ...`), so each language writes its own plurals and word order. Dates, amounts and
lists of names go through `formatters(locale)` (`@wishalia/i18n`), built on `Intl`.

In a Svelte component:

```svelte
<script lang="ts">
  import { appMessages } from "@wishalia/i18n/messages/app";
  import { useI18n } from "@wishalia/ui/i18n.ts";

  const i18n = useI18n();
  const m = $derived(appMessages(i18n.locale).settings);
</script>

<h1>{m.title}</h1><p>{i18n.fmt.money(1250)}</p>
```

The codes the API answers with (`invalid_request`, `already_reserved`...) never change: each frontend
turns them into words.

## The CI check

`packages/i18n/src/messages/catalog.test.ts` runs with the other tests, and so in the CI. For every
area and every language it checks that:

- each French key is there, of the same kind (a text, a function taking as many values, a list of the
  same length);
- no text is empty;
- each function writes a sentence for any count (0, 1, 2, 12) and any name.

## Adding a language

1. Add its code to `LOCALES` in `packages/i18n/src/locales.ts`, with its own name in `LOCALE_NAMES`
   (« Deutsch ») and its regional tag in `LOCALE_TAGS` (`de-DE`), which sets the format of dates
   and amounts.
2. Copy `packages/i18n/src/messages/en/` to `messages/<code>/`, translate each file, and add the new
   catalog to each `messages/<area>.ts`.
3. `pnpm typecheck && pnpm test`: the type checker and the catalog check name every key that is
   missing.
4. Add the code to the values `DEFAULT_LOCALE` takes (`docs/configuration.md`, `docs/chart-values.md`).

Nothing else changes: the settings, the header buttons and the browser negotiation read `LOCALES`.
